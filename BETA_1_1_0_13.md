# AirPortRTW 1.1.0 Beta 13

Build: `1.1.0-beta.13-control-coordination`; numeric bundle versions: `1.1.0`.
Branch: `1.0.0-beta`. Package: one ZIP with kext, executable helper and these notes.

## Changes

- BTM requests can wait for the existing RRM/scanner owner, within the AP's
  original deadline. No scanner is canceled or duplicated in the receive callback.
  An active measurement finishes before BTM evaluation; additional queued
  measurements may receive a refusal so BTM can proceed. Deadline, power,
  source, RF freshness, security, cooldown and response-ACK checks still apply.
- A separate `btm_ingress_*` snapshot records incoming token, mode, source and
  admission/rate-limit outcome without overwriting the active transaction's
  `btm_outcome_*` decision or ACK identity. Deferrals are counted.
- `rm_failure_*` retains the last refused/incapable request's wire context:
  operating class, channel, dialog/token, type, mode, duration, flags and reason.
  A later successful report does not erase it. `rm_last_*` describes the latest
  processed request; `rm_plan_*` counts the latest channel-plan filtering.
- Unknown operating classes receive an explicit incapable reply; a channel
  outside a supported class, absent/disabled regulatory channel, and an active
  measurement on a passive-only/DFS channel have distinct refusal reasons.
  No guessed country-specific class mapping or regulatory bypass is added.
- Auto-roam pending labels in each snapshot use live flags, eliminating the
  stale label between the one-second watch and five-second control ticks.
- Beta 12 scan backpressure, persistent wake timing and queue/drop diagnostics
  remain enabled. Boot argument `-rtwnoautoroam` disables automatic roaming.

## What is still unconfirmed

The Beta 12 trace did not retain the operating class for the refused channel-5
measurement. This build identifies the precise reason on a new occurrence; it
does not claim that the original request is now supported. The implemented RRM
channel mapping covers global 20 MHz classes 81/82/115/118/121/124/125 only.
Beacon report interoperability and AP-initiated accepted BTM switches still
require hardware testing. A report's Wi-Fi ACK is not proof that the AP used
the measurement. FT/802.11r, PMF/WPA3 and other optional k/v services are not
added. Initial wake reconnect delay remains under investigation.

## Regression checks

Host tests execute production RRM and BTM together, including an in-flight
measurement, competing tokens, one scanner, ACK-before-switch, deadline expiry
and PM cancellation. Additional cases cover channel rejection categories,
failure retention and live snapshot labels. Native macOS CI compiles kext/helper,
checks the plist, x86_64 architecture and compiled IOCTL stack budgets.
Host mocks do not validate RF behavior or prove absence of kernel panics.

## Test before RC1

Install the kext, reboot and check the actual loaded build:

```sh
ioreg -r -c AirPortRTW -l | grep DriverBuild
```

In the extracted package directory:

```sh
sudo ./rtw88-roam --log-level verbose
sudo ./rtw88-roam --watch 300 > ~/Desktop/AirPortRTW-Beta13-Watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-Beta13-After.txt
```

Walk between the APs during the watch; test several return switches and
2.4/5 GHz transitions. Verify Internet access independently. Compare
`btm_ingress_*`, `btm_outcome_*`, `btm_deferred_measurements`, `rm_failure_*`,
`rm_last_opclass`, `rm_plan_*` and queue/drop counters.

For a separate sleep test, save a report immediately after wake and another
after Internet access works. `wake_*_ms` is relative to driver restore entry;
`-1` means not observed. RC1 depends on these hardware tests and sustained use.
