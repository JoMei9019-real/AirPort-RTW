# AirPortRTW 1.1.0 Beta 12

Build: `1.1.0-beta.12-lifecycle-diagnostics`; numeric bundle versions: `1.1.0`.

## Changes

- Connected off-channel software scans stall output without freeing the queued
  mbuf. Home slots and scan completion resume the existing asynchronous queue.
  Native output gating also prevents pulling more traffic while off-channel.
- Operating class zero in FRITZ Neighbor Reports is accepted as an unknown
  channel hint. BSSID, lengths, token and source checks remain enforced. Actual
  joins still require fresh RF evidence, compatible security and allowed channels.
- Auto-roam pending labels are refreshed once the operation ends.
- Wake timing is retained separately from the bounded log: radio-ready, first
  scan, authentication, association, keys, first delivered non-EAPOL frame and
  first keyed BSSID/channel. Times are milliseconds since the driver's wake
  restore entry; -1 means not observed. These do not measure Internet reachability.
  Initial CoreWiFi reconnect latency is being measured, not declared fixed.
- BTM retains source, candidate, token, request/decision/ACK/switch times,
  validation reason/result and remaining cooldown across later auto scans.
  Busy/rate-limited requests do not replace an active transaction's record.
  Switch time means submission, not successful association. The 60-second
  cooldown and security/DFS validation remain enforced.
- Queue totals/deltas are sampled every five seconds, with separate driver
  stall/drop reason counters. A counter increase can include queue overflow;
  the previously observed cumulative drops are not all attributed to one cause.

## Test

Replace the kext and reboot. Check `DriverBuild` before testing:

```sh
ioreg -r -c AirPortRTW -l | grep -E 'DriverBuild|ROAM_K_UNKNOWN_CLASS_HINTS'
sudo ./rtw88-roam --log-level verbose
sudo ./rtw88-roam --watch 300 > ~/Desktop/AirPortRTW-Beta12-Watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-Beta12-After.txt
```

During the watch, move closer to the other AP and keep browsing. Test sleep
separately and save a report immediately after waking, then another after the
connection works. Compare `wake_*`, `btm_outcome_*`, `queue_*`, `tx_*` and
`neighbor_unknown_class_hints`. Check Internet access separately.
Automatic roaming remains enabled; boot argument `-rtwnoautoroam` disables it.

## Validation and limits

Host regression tests exercise production parsers/control/scanner paths with
mocked RF/OS, including a captured FRITZ response, retained mbuf ownership,
cooldown rejection persistence and wake timing across subsequent roaming.
Native CI compiles the kext/helper and checks IOCTL stack budgets and plist.
Hardware tests are still required for packet loss, wake latency, Beacon
Measurement requests and AP-initiated accepted BTM switches. Router k/v labels
confirm advertised capabilities, not full interoperability. FT/802.11r is absent.

Package: one ZIP containing the kext, executable helper and these notes.
