# 1.1.0 Beta 6 — repeatable roaming diagnostics

Experimental branch: `1.0.0-beta`. Stable `main` is unchanged.
Numeric bundle version remains `1.1.0`; identify the build using
`DriverBuild = 1.1.0-beta.6-roam-diagnostics`.

## Install once

Extract the archive. Copy only the inner `AirPortRTW.kext` bundle to
`EFI/OC/Kexts/`, preserving `AirPortRTW.kext/Contents/Info.plist` directly.
Keep `rtw88-roam` outside the kext. Reboot once after replacing the driver.
Both `RoamingAssistEnabled` and `RoamingSwitchEnabled` are enabled in the
RTL8821CE personality. Other card personalities retain their opt-in behavior.

Subsequent log-level changes, Neighbor Report refreshes, preflight checks and
manual switch tests do not require rebooting or toggling Wi-Fi. A change to
compiled driver code still requires installing a new build and rebooting.

## Commands

Run these from the extracted folder:

```sh
./rtw88-roam --status
sudo ./rtw88-roam --log-level verbose
sudo ./rtw88-roam --refresh
./rtw88-roam --neighbors
```

Use a real BSSID from that fresh report in place of `aa:bb:cc:dd:ee:ff`:

```sh
sudo ./rtw88-roam --check aa:bb:cc:dd:ee:ff
sudo ./rtw88-roam --scan aa:bb:cc:dd:ee:ff
sudo ./rtw88-roam --prepare aa:bb:cc:dd:ee:ff
sudo ./rtw88-roam --roam aa:bb:cc:dd:ee:ff
```

- `--check` executes eligibility checks without disconnecting or scanning.
- `--scan` visits exactly the reported neighbor channel and returns home.
- `--prepare` refreshes the report, scans the candidate channel and checks
  eligibility, without requesting an AP switch.
- `--roam` performs refresh + scan + switch in sequence. Any failing step stops
  the sequence before the switch. A raw BSSID argument retains Beta 5's direct
  switch using existing fresh report/scan data.
- Refresh waits at most 12 seconds; a target scan waits at most 8 seconds.
  Kernel requests return asynchronously and do not sleep on the controller gate.
  New refreshes and target scans are rate-limited to once per 5 seconds.
  An automatic initial request can cause an immediate explicit refresh to return
  `neighbor-request-pending` or `neighbor-request-rate-limited`; inspect status
  and retry after that request finishes and the 5-second limit has passed.

Monitor outcome and collect the existing bounded ring without draining it:

```sh
sudo ./rtw88-roam --watch 45 > ~/Desktop/AirPortRTW-roam-watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-roam-report.txt
sudo ./rtw88-roam --log-level normal
```

`--status`, `--watch` and `--report` can be read without root, using periodic
snapshots (up to approximately 5 seconds old). With sudo they explicitly request
a current software snapshot. Status/report do not tune the radio or initiate
authentication. `--watch` is bounded to 1–3600 seconds; default 60 seconds.
It also appends newly published driver-ring events after its initial sample,
and indicates if the bounded ring has overrun between samples.
The report can contain network names and MAC addresses from existing logs.

## What the diagnostics mean

`ROAM_DIAGNOSTICS` contains structured text. Important fields:

- `test_id`, `stage`, `stage_age_ms`: the most recent test operation and stage.
  A switch keeps its ID through authentication and its single fallback.
- `reason`, `request_result`: exact preflight reason and hexadecimal IOReturn.
- `neighbor_age_ms`, `neighbor_fresh`, `neighbor_count`, `last_response_count`:
  distinguish an expired list from a valid reply with zero candidates.
- `neighbor_pending`, request/response/invalid/timeout counts and dialog token.
- `checked_scan_age_ms`, target RSSI/channel/regulatory flags and current BSSID.
- `scan_active`, `scan_result`, `scan_engine`, `scan_worker_pending`.
  Scan results: 0 none, 1 running, 2 completed, 3 aborted, 4 start failed.
  Completion means the scan worker completed; it does not prove RF reception.
- `switch_phase`, `switch_result`, `cooldown_remaining_ms`, authentication worker
  state, PTK/GTK presence, AP disconnect reason and delivered non-EAPOL RX count.
- Ages of `-1` mean no observation/time available, not a negative elapsed time.

Rejections distinguish missing/stale Neighbor Reports, a target not in the
report or scan cache, SSID/channel mismatch, weak/invalid signal, stale scan,
incompatible security, missing/disabled/no-IR/DFS channels, active workers,
power transition, unsupported connection state and the switch cooldown.

`ROAM` event lines contain test ID, monotonic milliseconds, stage, detail,
connection state, power/link/key-presence flags, AP BSSID and channel. Events
cover Neighbor Report TX/RX/empty/invalid/timeout/expiry, target scan, RF setup,
authentication TX/response/AP status, association TX/response/AP status,
EAPOL M1/M3, MIC or key-install failures, M4 submission, AP deauth/disassoc,
timeouts, cancellation and one fallback. Verbose additionally records each
neighbor's BSSID/channel/operating class/preference. Logging is event-driven;
no per-data-packet logs or new key, nonce, password or payload dumps are added.
`--log-level off` suppresses the new ROAM event lines, while status and existing
driver diagnostics remain available. The shared ring is 32 KiB and can wrap.

## Scope and hardware validation

The connected scan is an explicit diagnostic operation using the existing
software scanner, one permitted non-DFS channel, STA power-save notification
and home-channel restore. Normal CoreWiFi background scans remain cache-only.
It may briefly interrupt traffic. It is not a general connected full-band scan.
No DFS/no-IR safety gate is bypassed to make the test succeed.

WPA2-Personal/CCMP only, fresh report and scan data (<30 seconds), identical
SSID, RSSI at least -80 dBm, and a 60-second switch cooldown remain required.
There is no automatic signal-based roaming, 802.11r FT, PMF or WPA3 support.

Switch results retain Beta 5's meanings: 0 none, 1 target pending, 2 fallback
pending, 3 target locally keyed, 4 original AP locally keyed, 5 both failed,
6 canceled. Each attempt is bounded by the existing 15-second deadline checked
on the diagnostic timer; a running authentication worker must exit before the
fallback can proceed. Completion can therefore exceed the nominal deadline.

Local keys/M4 submission and management-frame TX submission do not prove AP
acceptance, radio ACKs or IP reachability. Confirm the resulting BSSID, access
to the gateway and actual data transfer after a switch. RX delivery counts
are observations, not an Internet connectivity test.

Host regression tests execute production validation, refresh, trace/snapshot
and one-channel scan paths with mocked OS/firmware operations, including TTL,
rate limits, regulatory rejection, power gating, PS/home-restore call ordering,
bounded snapshots, key snapshot/erasure and one-shot fallback. Native CI builds
the x86_64 kext/helper and checks the existing compiled IOCTL stack budgets.
These checks do not establish over-air scan/roam or sleep reliability on hardware.
