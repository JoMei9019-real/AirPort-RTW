# 1.1.0 Beta 9 — automatic roaming and Neighbor Report diagnostics

Branch: `1.0.0-beta`; bundle version `1.1.0`.
DriverBuild: `1.1.0-beta.9-auto-roam`. Stable main is unchanged.

## Automatic AP selection

RTL8821CE's personality enables `RoamingAutoEnabled`, `RoamingAssistEnabled`
and `RoamingSwitchEnabled`. Other cards remain opt-in. The existing five-second
controller timer executes the policy under the existing power-transition fence.
No new worker, timer or user-space daemon is added.

- First observation warms up for 30 seconds after a connection. The next tick
  starts a bounded discovery scan. Selection occurs on a subsequent timer tick
  after the scanner returns home and relinquishes ownership.
- The scan must complete successfully and retain its generation. Aborted or
  replaced scans cannot trigger an automatic switch.
- Candidates require actual fresh scan results, same SSID, supported WPA2-PSK
  CCMP security, regulatory eligibility and keys on the existing connection.
  DFS/no-IR targets still require matching fresh beacon proof.
- Prefer 5 GHz at -70 dBm or stronger; retain current 5 GHz down to -77 dBm.
  Other usable links must be at least -80 dBm. Same-band changes require 6 dB
  improvement. The current AP participates in selection; no forced switching.
- A successful scan is followed by at least 60 seconds before another scan.
  Failed scan submissions also wait 60 seconds. Switching retains the existing
  60-second cooldown, fresh WPA2 handshake and one old-AP fallback.
- Manual refresh/check/scan/selection/switch commands clear any pending automatic
  decision and pause automatic discovery for 60 seconds. Snapshots, reports,
  watches and log-level changes do not pause the policy.
- Power-off, disassociation and key cleanup discard pending automatic decisions.
  The boot argument `-rtwnoautoroam` disables automatic AP changes for the boot.
  Manual switching and Neighbor Report diagnostics remain available.

This is periodic selection, not seamless 802.11r Fast Transition. Full discovery
currently takes about 6.4 seconds on the tested setup and may affect latency.
Automatic operation and cross-channel switching need hardware validation.

## 802.11k/v advertisement

The association request advertises only the implemented Neighbor Report portion
of 802.11k: Radio Measurement capability plus the Neighbor Report bit in the RM
Enabled Capabilities IE. It is conditional on roaming assistance, supported WPA2
security and the AP's advertised capability. It does not claim beacon or link
measurements. `ROAM_K_ADVERTISED` records whether that IE was built; a router may
display capabilities differently and this is not an over-air capture.

802.11v BTM handling still parses requests and sends bounded rejections. It does
not yet accept and execute a requested BTM transition, so it remains unadvertised:
`ROAM_V_ADVERTISED=No`. Independent automatic AP selection does not change that.
FT, PMF and SAE are not added.

## Neighbor Report diagnostics

Requests now refresh throughout a connection, bounded to one per minute even on
TX failure. Rejections retain strict parsing, source, token and timeout guards.
The report identifies `neighbor_reject`, parser reason, offset (relative to the
action body), element ID/length, remaining bytes, candidate index, actual token
and response age. The expected token is `neighbor_token` and is logged with the
rejection. At verbose level a maximum 32-byte management-body window around the
failing position helps reproduce the parser case. These windows contain AP
metadata/BSSIDs, never data packets or EAPOL keys. Log level off suppresses them.
These fields describe the last received response, not the current link state.
The reproducible Beta 8 response rejection is not claimed fixed without its bytes.

## Install and test

One ZIP contains `AirPortRTW.kext/`, executable `rtw88-roam` and these notes at its
root. Replace the kext in `EFI/OC/Kexts/`, reboot once and verify DriverBuild.
From the extracted directory, enable verbose logging and observe automatic work:

```sh
sudo ./rtw88-roam --log-level verbose
sudo ./rtw88-roam --watch 180 > ~/Desktop/AirPortRTW-Beta9-Auto-Watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-Beta9-After.txt
```

Do not issue manual discover/roam commands during this observation. Stay where a
better AP is reachable, or move toward it. Confirm BSSID changes and usable IP
traffic. Status includes `auto_enabled`, `auto_stage`, `auto_next_ms` (absolute
monotonic time), pending scan, scan/switch-submission counts, and live gate inputs.
`auto_switches` counts submissions, not successful completions; check
`switch_result`, final BSSID and traffic. To disable automatic changes, add this
to OpenCore's `boot-args` and reboot:

```sh
-rtwnoautoroam
```

Remove the argument and reboot to restore the personality's default. There is
no runtime `--auto` toggle. `ROAM_AUTO_DISABLED_BY_BOOT_ARG` reports this override;
`ROAM_AUTO_ENABLED` reports the effective policy setting.

## Validation limits

Host regression tests execute production scheduler/parser/scan/switch methods
with mocked RF/OS interfaces, including warmup, discovery, selection, cooldown,
manual precedence, power cancellation, parser diagnostics and malformed input.
Native compilation and stack checks do not prove hardware stability. Earlier
manual same-channel switches worked on Beta 8; automatic and cross-channel
operation, long sleep and the unexplained Beta 7 boot panic remain unvalidated.
