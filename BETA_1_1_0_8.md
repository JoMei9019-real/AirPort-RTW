# 1.1.0 Beta 8 — roaming preflight and scan-channel coherence

Branch: `1.0.0-beta`. Numeric bundle version: `1.1.0`.
DriverBuild: `1.1.0-beta.8-roam-preflight`. Stable `main` is unchanged.

## Changes

- Distinct rejection reasons: `not-connected` (state), `link-not-visible`,
  `authentication-cancelled`, `awdl-off-channel`, `home-channel-not-restored`.
- Explicit control ends an AWDL off-channel window only after power, connected
  state, visibility, auth worker, keys and security checks pass. It verifies the
  restored home channel before continuing. It does not clear auth cancellation.
- AWDL cannot request a channel while the explicit roaming scanner or switch
  owns the PHY. An idle connected link remains available for AWDL scheduling.
- Scan entries use the AP's DS/HT primary channel and matching frequency from
  the enabled regulatory table, rather than mixing it with an adjacent channel
  on which the frame was received. Disabled/unknown channels stay ineligible.
- Beacon proof uses the original RX frequency, so metadata normalization cannot
  manufacture proof for a DFS/no-IR channel.
- Status and event logs include `auth_cancelled`, `awdl_off_channel`, worker
  state and a rejection-time `last_gate_flags` snapshot. Bits 0..4 are connected,
  visible, auth-cancelled, AWDL-off-channel, auth-worker-active respectively.
  The snapshot records the last preflight; the other fields are live observations.

## Install and test

One ZIP contains the kext, executable helper and these notes directly. Replace
the kext in `EFI/OC/Kexts/` and reboot once. Keep the helper outside the kext.
Both roaming switches default to true for RTL8821CE; other cards remain opt-in.

From the extracted directory:

```sh
sudo ./rtw88-roam --log-level verbose
sudo ./rtw88-roam --roam 04:b4:fe:8b:30:11
sudo ./rtw88-roam --watch 45 > ~/Desktop/AirPortRTW-Beta8-Watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-Beta8-After.txt
```

Use a BSSID in your own network if different. `--roam` performs discovery first.
Afterwards verify the target BSSID and usable IP traffic (browser or LAN ping).
Accepted submission or locally installed keys alone do not prove AP acceptance.
`--status`, `--aps`, `--best` and `--report` remain available without restarting.
Old `reason`/`stage` values remain until another command/event updates them;
repeated watch lines are not repeated failed requests.

## Validation limits

Host regression tests use mocked firmware/OS interfaces. Native compilation and
stack checks do not validate RF operation. The exact Beta 7 rejection input was
not recorded, so its resolution needs this hardware test. The earlier reported
boot panic is still unexplained and is not claimed fixed. DFS interoperability,
sleep/wake stability and successful AP switching need hardware validation.
No background automatic roaming, 802.11r FT, SAE or PMF is added.
