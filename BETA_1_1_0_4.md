# AirPortRTW 1.1.0 Beta 4 — k/v/r foundations

Branch: `1.0.0-beta`, based on 1.1.0 Beta 3. Numeric bundle/kmod version:
`1.1.0`. DriverBuild: `1.1.0-beta.4-roaming-foundations`.

## Implemented scope

This is a first protocol/diagnostic step, **not full 802.11k/v/r support**.

| Area | This beta | Not implemented |
| --- | --- | --- |
| 802.11k | Opt-in Neighbor Report request, matching response parsing and bounded cache | Beacon/link measurements, targeted scans, automatic candidate selection |
| 802.11v | Parse BTM requests, validate optional fields/candidates, submit rejection response | Accepting a transition, moving to another BSSID, other WNM services |
| 802.11r | Parse AP Mobility Domain ID/policy and FT-802.1X / FT-PSK AKMs | FT authentication/reassociation, PMK-R0/R1, FT MIC/key installation |

AP metadata is reported even with active testing disabled. Active operations
are limited to a fully keyed, associated internal WPA2-Personal/CCMP session,
on the infrastructure channel. Open, Enterprise, external supplicant,
PMF-required and WPA3 connections are outside this initial active scope.

The driver advertises only Neighbor Report capability, and only in opt-in
eligible association requests when the AP has advertised that feature. It
does not advertise BTM or FT capabilities. Consequently a normal AP may never
send a BTM request to this client; use a controllable test AP to exercise that
path. We intentionally do not promise or falsely accept a transition that
the driver cannot yet carry out. An AP may still disconnect a client after a
BTM rejection; rejection is not a guarantee that it will keep the client.

## Safety and lifecycle

- No extra kernel thread or timer. The existing controller diagnostics timer
  (initial 1-second sample, then 5-second samples) drives one Neighbor Report
  submission attempt per eligible association. Submission is not TX ACK proof.
- Responses require the current AP as transmitter/BSSID, our unicast receiver
  address, a matching nonzero dialog token and a response within 5 seconds.
- At most 16 unique reported neighbors are retained; overflow is marked.
  Remaining elements are still validated. Cache expires after 30 seconds,
  at the next timer sample, or immediately on key/session teardown.
- Neighbor information is untrusted topology advice, not proof of matching
  SSID, security, regulatory permission or reachability. No channel changes,
  scans, key reuse or automatic roam are triggered by it.
- BTM responses always reject (status 1), echo the dialog token and are
  rate-limited to at most one submission attempt per second. URL fields are
  length-checked and discarded, never followed or logged.
- Protected, fragmented, malformed, oversized and wrong-peer action frames
  are excluded from this non-PMF experimental path. On WPA2 without PMF an
  address match is not cryptographic proof of the sender.
- Sleep/shutdown/DMA-stop, Wi-Fi off, scan, incomplete keys and AWDL off-channel
  ownership block active handling. `clearKeys()` resets session/candidate
  state and retains only the rolling token sequence and lifetime counters.
- No new secret/packet logging. Registry diagnostics use counts and AP
  capability/domain fields, not neighbor MAC lists or password/key material.

## Enable the active test (default OFF)

First back up the working EFI. In **the copy of this beta** installed in
`EFI/OC/Kexts/AirPortRTW.kext/Contents/Info.plist`, add a Boolean
`RoamingAssistEnabled = true` inside the matching `IOKitPersonalities` entry.
For an RTL8821CE this is `AirPortRTW_8821CE` (not the plist root and not an
OpenCore boot argument). Reboot after changing it.

Example, run from the directory containing the beta kext:

```sh
/usr/libexec/PlistBuddy -c 'Add :IOKitPersonalities:AirPortRTW_8821CE:RoamingAssistEnabled bool true' AirPortRTW.kext/Contents/Info.plist
```

If the key already exists use `Set ... true` instead of `Add ... bool true`.
Use `AirPortRTW_8822BE`, `AirPortRTW_8822CE` or `AirPortRTW_8814AE` only if that
is the matching chipset entry. Set the Boolean to false and reboot to disable.
Do not enable FT-only or WPA3/PMF-required security expecting this beta to join.

## Test and interpret diagnostics

Connect to a WPA2-Personal/CCMP AP that advertises Neighbor Reports. Then:

```sh
ioreg -r -c AirPortRTW -l | grep -E 'DriverBuild|ROAM_|PM_LAST'
```

Expected:

- `ROAM_ASSIST_ENABLED=Yes` only after the opt-in property is applied.
- `ROAM_AP_NEIGHBOR_REPORT=1` if the connected AP's cached IEs advertise it.
- `ROAM_K_REQUEST_SUBMITTED` increases by one after an eligible association.
- `ROAM_K_RESPONSE_RX` increases only on a valid matching response.
- `ROAM_K_NEIGHBOR_COUNT` may be zero even after a valid empty response;
  a nonzero count indicates cached reports, not an actual AP switch.
- `ROAM_K_RESPONSE_TIMEOUT` increments if no valid response arrived in time;
  there is deliberately no retry loop to interfere with sleep/traffic.
- `ROAM_AP_BTM`, `ROAM_AP_MOBILITY_DOMAIN`, `ROAM_AP_MDID`, `ROAM_AP_FT_POLICY`
  and `ROAM_AP_FT_AKMS` describe AP data, **not client support**. `FT_AKMS`
  bit 0 means FT-802.1X and bit 1 means FT-PSK. `ROAM_R_FT_ENABLED` stays false.
- A manual BTM test should increase `ROAM_V_REQUEST_RX` and
  `ROAM_V_REJECT_SUBMITTED`. `ROAM_V_DISASSOC_TIMER_TBTT` is in beacon intervals,
  not milliseconds. `ROAM_V_MODE` remains `reject-only`.

Telemetry refresh follows the existing diagnostics cadence. Request/response
counters persist for the boot; current session metadata/cache resets on
teardown. With radio off, last published registry samples may remain visible.

Test baseline traffic, network switching through macOS, Wi-Fi off/on and sleep
both with the property disabled and enabled. Confirm no new unexpected AP
switch, deauth loop, handshake failure or sleep blocker. A FRITZ mesh network
is useful only if the AP advertises/sends the relevant messages; being in a
mesh alone does not prove that k/v exchanges occurred.

## Verification and references

`tests/check_roaming.py` executes the production parser and runtime methods
with mocked TX/PM state under ASan/UBSan, including 30,000 malformed inputs,
source/header/token checks, bounded/truncated reports, BTM optional fields,
default-off, failure/timeout/expiry and teardown. Build integration checks
verify that FT/BTM are not advertised and that the existing PM fence wraps
the new tick. All previous suites and compiled IOCTL stack budgets remain.
This is not over-air or full XNU scheduling validation.

Wire constants/layout were checked against the hostap project definitions:
https://w1.fi/wpa_supplicant/devel/ieee802__11__defs_8h_source.html

The implementation is independently written; no SAE/PMF/FT implementation was
copied or added. WPA2-Enterprise remains experimental and unvalidated on a
live EAP network, as documented in the earlier beta notes.
