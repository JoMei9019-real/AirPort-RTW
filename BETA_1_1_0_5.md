# 1.1.0 Beta 5 — controlled WPA2-Personal AP switch

DriverBuild: `1.1.0-beta.5-controlled-roam`; numeric bundle version: `1.1.0`.
Based on Beta 4 on `1.0.0-beta`. This is a manual, experimental reconnect
between APs; it does not implement 802.11r, seamless roaming or automatic BTM
acceptance. Expect a traffic interruption and a fresh WPA2 four-way handshake.

## Enable and test

Keep a working EFI backup. In the matching `IOKitPersonalities` entry of the
installed beta's `AirPortRTW.kext/Contents/Info.plist`, set both Booleans:

- `RoamingAssistEnabled = true` (Beta 4 Neighbor Reports)
- `RoamingSwitchEnabled = true` (new manual switching; default false)

For RTL8821CE, the matching entry is `AirPortRTW_8821CE`. Reboot after editing.
Neither setting is an OpenCore boot argument. FT and WPA3 are not enabled.

The ZIP includes an x86_64 `rtw88-roam` tool. In Terminal, change to the extracted
directory. Immediately after connecting and receiving a Neighbor Report:

```sh
./rtw88-roam
```

This lists cached neighbor BSSIDs. Choose one of these, replacing the example:

```sh
sudo ./rtw88-roam aa:bb:cc:dd:ee:ff
ioreg -r -c AirPortRTW -l | grep -E 'DriverBuild|ROAM_SWITCH|ROAM_K_'
```

The request is accepted only with both switches enabled, an internal fully
keyed WPA2-Personal/CCMP connection, no scan/AWDL channel ownership or power
transition, and a reported neighbor. The candidate must also have been seen
in an actual scan less than 30 seconds ago with identical SSID, CCMP group/
pairwise support and PSK AKM, no required PMF, RSSI at least -80 dBm, and a
matching enabled non-DFS/non-NO_IR channel/frequency in the hardware table.

This beta uses the recent scan cache; it does not yet scan off-channel while
connected. A Neighbor Report alone does not refresh scan observations. A stale,
missing or unsuitable candidate is rejected before disconnecting. If rejected,
try after a new macOS scan/reconnection; do not interpret rejection as proof the
AP lacks roaming. Report the error and diagnostics if no fresh candidate exists.

Root authorization and a six-byte input are checked in the service. The request
is serialized on the controller workloop. There is no password argument or key
output. The service property is a command, not a persistent target setting.

## Outcomes

`ROAM_SWITCH_REQUEST_RESULT=0` means the request started, not that it succeeded.
`ROAM_SWITCH_RESULT` updates on the existing diagnostic timer (up to 5 seconds):

| Value | Meaning |
| --- | --- |
| 0 | No transaction yet |
| 1 | Target authentication/handshake pending |
| 2 | One reconnect to the previous AP pending |
| 3 | Target reached local keyed CONNECTED state |
| 4 | Previous AP reached local keyed CONNECTED state |
| 5 | Both attempts ended without a keyed connection |
| 6 | Transaction canceled by OS/user/power handling |

Each attempt is limited to 15 seconds, observed by the existing 5-second timer;
the ordinary authentication timers may fail sooner. Requests have a 60-second
cooldown. A timed-out auth worker is canceled and allowed to exit before
fallback cleanup; this may extend the deadline, avoiding a controller/worker
wait cycle. Requests have a 60-second
cooldown. There is no endless retry loop. CoreWiFi may independently select a
network; a new macOS association request cancels this experimental transaction.
User disconnect and power-off cancel it too. The temporary PMK snapshot is
explicitly erased on completion, failure or cancellation. Old PTK/GTK keys and
packet counters use the existing disconnect/new-handshake cleanup.

Check the actual BSSID in macOS/Starskiff and verify sustained traffic. Result 3
or 4 proves only the local keyed state, not AP acceptance or working IP traffic.
Compare Wi-Fi off/on and sleep with switching disabled/enabled. No live hardware
switch has been validated by the build process. The AP can disappear or reject
either handshake, so fallback is best effort. Neighbor MACs are now exposed in
the local registry/tool for selecting targets; redact them before sharing logs.

## Validation

`check_roam_switch.py` runs the production request/state-machine methods with
mock association/firmware calls under ASan/UBSan: eligibility, stale/mismatched
scan/security/regulatory rejection before teardown, PMK snapshot, target success,
one fallback, timeout, cancellation and secret erasure. Existing parser, RX,
sleep, Enterprise, TX batching and compiled stack-budget checks remain enabled.
The helper is compiled on macOS; the actual IOKit command path and RF behavior
still need hardware tests. WPA2-Enterprise remains experimental as before.
