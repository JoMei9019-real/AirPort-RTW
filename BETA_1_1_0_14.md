# AirPortRTW 1.1.0 Beta 14

Build: `1.1.0-beta.14-tx-flow-control`; numeric bundle versions: `1.1.0`.
One ZIP contains the kext, executable `rtw88-roam` and these notes.

## Changes

- Native `outputStart` gating now checks AWDL ownership before pulling packets,
  alongside the existing scan, ring-watermark and family-queue gates.
- Connected AWDL off-channel ownership is published before the settling delay
  and retune. Per-packet stall retains mbuf ownership; home/reclaim release
  remains asynchronous with existing hysteresis and PM guards.
- New counters: `tx_submitted`, `tx_start_calls`, `tx_gate_awdl_checks`,
  `tx_gate_scan_checks`, `tx_gate_ring_checks`, `tx_gate_depth_checks`,
  `tx_queue_resumes`, `awdl_hops_performed`, `awdl_hops_blocked`,
  `awdl_hop_runtime_changes`. Gate checks can occur more than once per callback.
  Submission is not RF ACK or successful application traffic.
- Live commands: `sudo ./rtw88-roam --awdl-hops off` and `on`.
  No reboot is needed between comparison runs. Off restores the AP channel
  before restarting queued infrastructure output, then rejects AWDL retunes.
  A failed home restore returns an error and retains the output-blocking latch.
  Active scan/auth/roam/measurement owners return Busy; retry after completion.
  The command does not pause automatic roaming or cancel measurements.
- Optional boot argument `-rtwnoawdlhop` starts with hopping disabled. Runtime
  commands can override that initial setting until the next boot. Without the
  boot argument, hopping starts enabled. Runtime policy survives sleep/wake
  but resets on reboot. `awdl_hops_disabled` reports the effective policy;
  `AWDL_HOPS_DISABLED_BY_BOOT_ARG` only describes the boot argument.

Off applies only to AWDL retunes, including idle discovery. Same-channel AWDL
can still operate subject to normal state/regulatory checks. The AWDL interface
is not removed. Cross-channel discovery/AirDrop may stop while Off. Normal
infrastructure scans and roaming are not disabled by this policy.

## Why this build

Beta 13 had no new queue drops in a five-minute low-load run, but 8,717 new
drops during a roughly 68-second speedtest with no AP change. The user reported
120 Mbit/s down and 50 Mbit/s up (the contractual upload limit). These observations
identify a load-related problem, not its cause. The early AWDL gate mismatch
is corrected here; neither that correction nor AWDL's causal role is hardware
validated yet. Queue depth, RF timing, security and regulatory restrictions are
not relaxed. RC1 remains pending load, roaming, BTM/RRM and sleep tests.

## Test without repeated reboots

Install this kext once and reboot. Use the helper supplied in this same ZIP.

```sh
ioreg -r -c AirPortRTW -l | grep DriverBuild
sudo ./rtw88-roam --log-level verbose
sudo ./rtw88-roam --awdl-hops on
sudo ./rtw88-roam --watch 90 > ~/Desktop/AirPortRTW-Beta14-HopsOn-Watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-Beta14-HopsOn-After.txt
```

Start the same browser speedtest while Watch runs, at the same location/AP.
Record download/upload speeds. Then, without restarting:

```sh
sudo ./rtw88-roam --awdl-hops off
sudo ./rtw88-roam --status | grep -E 'awdl_hops_|awdl_hop_runtime_changes'
sudo ./rtw88-roam --watch 90 > ~/Desktop/AirPortRTW-Beta14-HopsOff-Watch.txt
sudo ./rtw88-roam --report > ~/Desktop/AirPortRTW-Beta14-HopsOff-After.txt
```

Verify `awdl_hops_disabled=1` after the Off command succeeds. Repeat the same
speedtest during Watch. Compare increases, not cumulative totals. In Off mode,
`awdl_hops_performed` should stop increasing; blocked attempts may increase.
If either run roams to another AP, repeat the comparison at a stable location.
Restore normal behavior with `sudo ./rtw88-roam --awdl-hops on`.

## Verification scope

Host tests execute production gate/restart and AWDL channel-policy methods with
OS/RF mocks: early gating, queue-depth/ring hysteresis, asynchronous restart,
PM suppression, live disable/enable, failed restore, owner-busy rejection and
no regulatory bypass. Existing scanner/ownership, RRM/BTM, sleep and stack tests
remain in CI. Native macOS CI builds the kext/helper and checks bundle metadata,
x86_64 architecture and compiled IOCTL stack budgets. RF performance and absence
of panics cannot be proven by these mocks.
