# AirPortRTW 1.1.0 Beta 3 — stability checks

Branch: `1.0.0-beta`, based on 1.1.0 Beta 2. Numeric bundle/kmod version:
`1.1.0`. DriverBuild: `1.1.0-beta.3-stability-checks`.

## What changed

This beta improves regression detection, not the wireless protocol or sleep
implementation. Runtime code changes are limited to build/version labels;
Beta 2 TX batching and Beta 1 experimental WPA2-Enterprise remain unchanged.

- `tests/check_workqueue.py` extracts the production workqueue implementation,
  list operations and workqueue header. Under host threads/locks and ASan/UBSan,
  it checks cancellation of queued/executing work, simultaneous flush/cancel,
  rejection of cross-queue migration while executing, delayed cancellation,
  stale timer callbacks, timer-allocation failure and repeated item reuse.
- `tests/check_scan_rx.py` executes the production single- and multiple-scan
  ingress, timeout handler, home-channel restore and RX dispatcher. It checks
  request validation, coalescing, scan-start failure, connected cache-only
  completion, absent/synchronous scan-cancel callbacks, manual-scan abort,
  authentication cancellation and Enterprise timeout guards. It also checks
  deferred RF calibration during scans, bad-FCS rejection, short-frame
  rejection and exactly-once ownership across STA/AWDL RX dispatch.
- `tests/check_stack_budget.py` checks the compiled x86_64 `apple80211Request`
  and `handleRequestCOUNTRY_CODE` entry frames, each capped at 256 bytes including
  saved registers. Unknown stack adjustments or missing symbols fail the build.
  Its parser self-test runs before building; real binary inspection runs after.
- All five previous regression suites still run before packaging. A failing
  regression test or compiled stack-budget check prevents artifact upload.

These tests are independently written for this checkout. The reviewed Realtek
AirPort Family tests informed the choice of coverage; no source or test files
from its custom-licensed archive were copied into this beta.

## Limits

Host locks/timers, RF, firmware, packet-parser internals and OS callback targets
are simulated. ASan/UBSan tests disable leak detection for host compatibility.
They are not XNU scheduling tests, RF benchmarks or over-air security tests.
The stack gate checks two entry frames, not total call-chain stack use, and
does not replace recursion guards. No newly discovered runtime bug is claimed
fixed by this beta. Long/deep sleep, WPA2-Enterprise PEAP/EAP-TLS and TX batching
benefit still need physical testing. No SAE/WPA3, PMF or fast roaming was added.

## Hardware regression checklist

Keep a known-working EFI/kext backup and change only AirPortRTW for comparison.

1. Confirm `DriverBuild` is `1.1.0-beta.3-stability-checks`:

   ```sh
   ioreg -r -c AirPortRTW -l | grep -E 'DriverBuild|TX_BATCH_|PM_'
   ```

2. On WPA2-Personal, test 2.4 and 5 GHz, sustained download/upload, Wi-Fi
   off/on, disconnect/rejoin and opening the network list during traffic.
3. Repeat short sleep (~10 minutes) and a longer sleep. Verify automatic
   reconnect, real traffic and no panic; also verify Wi-Fi stays off over sleep
   when manually disabled. Record `PM_LAST_SLEEP_RESULT` and
   `PM_LAST_WAKE_RESULT` after waking. A zero result is not proof of deep sleep.
4. Retain the Beta 2 TX-batching A/B test in `BETA_1_1_0_2.md`.
   `TX_BATCH_PENDING` should settle to zero after traffic stops.
5. Enterprise requires a real WPA2-Enterprise AP with a properly trusted test
   certificate. A working Personal network/repeater does not validate EAP.

Useful logs immediately after waking:

```sh
sudo log show --last 15m --style compact --predicate 'process == "kernel" AND (eventMessage CONTAINS[c] "AirPortRTW" OR eventMessage CONTAINS[c] "rtw88")'
pmset -g log | grep -E 'Sleep.*due to|Wake.*due to' | tail -n 40
```

Redact SSIDs, MAC addresses and other identifying fields before sharing logs.
