# 1.1.0 Beta 2 — bounded synchronous TX batching

Branch: `1.0.0-beta`; baseline: 1.1.0 Beta 1.
DriverBuild: `1.1.0-beta.2-tx-batching`; numeric bundle/kmod version: `1.1.0`.

## Implementation

- Scope batching to the native STA's synchronous `outputStart`, under the
  controller command gate, with an execution-thread owner and RAII final flush.
- At most 32 aggregation-ready QoS data frames per doorbell group. A shorter
  remainder is flushed when the scope exits, including error/stall returns.
- No timer, additional packet queue, waiting for 32 packets, or new delayed work.
- EAPOL always requests an immediate kick. Management, AWDL, frames outside
  the owned scope, and non-aggregation-ready traffic retain immediate submission.
- Use the same rtw88 descriptor preparation, HCI write and ownership rules as
  upstream rtw_tx. The pinned core is unmodified. On rejected writes, free only
  the rejected skb and kick earlier accepted descriptors.
- Flush pending work before the existing power-off/DMA fence. The bridge will
  not write MMIO after RTW_FLAG_RUNNING is cleared.
- Do not replace net80211, add unknown IO80211 virtual calls, alter queue depth,
  increase ring sizes, or remove the existing TX backpressure hysteresis.

## Limits

This is an experimental optimization, not a proven speed increase. Apple's
output queue can schedule packet callbacks asynchronously: those callbacks
keep the immediate path and cannot be grouped by this scope. Hardware tests
must establish whether a useful group size is achieved on each OS version.
The counters alone do not prove RF aggregation or throughput improvement.

The Enterprise limitations from [Beta 1](BETA_1_1_0_1.md) remain unchanged;
PEAP/EAP-TLS interoperability still needs a physical AP test. RTL8814AE
also remains experimental. No new chip support or 2.0.0 beta feature merge.

## Diagnostics and A/B test

`ioreg -l -w0 -r -c AirPortRTW` exposes:

- `TX_BATCH_ENABLED` and `TX_BATCH_LIMIT` (32).
- `TX_BATCH_DEFERRED_FRAMES`: frames submitted without their own kick.
- `TX_BATCH_FLUSHES`: scope flushes and immediate/error kick requests within
  owned scopes, not an exact MMIO-write counter.
- `TX_BATCH_PENDING`: should settle to zero after traffic stops.

1. Keep Beta 1 or 1.0.2 in a fallback EFI, install Beta 2 and reboot.
2. Verify normal join, DHCP, network switching, reconnect and sleep/wake.
3. Save IORegistry before and after a sustained local upload (e.g. iperf3
   to another wired LAN machine). Compare throughput, packet loss and CPU
   load with the same AP, channel, band and client position.
4. To disable batching, set boolean `TxBatchingEnabled` to false inside this
   chip's matching `IOKitPersonalities` dictionary in the injected kext's
   Info.plist, then reboot. Do not place it at the bundle root. Restore/remove
   the property to re-enable. Repeat the same test; change no other settings.
5. If deferred frames remain zero, this OS/queue workload did not use the
   synchronous path. Do not report that as a successful batching speedup.

Host ASan/UBSan tests exercise production begin/end, submission tail and C
bridge with mocked DMA: partial/full batches, EAPOL, ring-full errors, nested
and foreign-thread calls, disabled mode and stopped-device ownership. They
do not reproduce Apple's queue scheduler, PCI DMA timing or RF behavior.
