# 1.1.0 Beta 1 — experimental WPA2-Enterprise

Branch: `1.0.0-beta`; baseline: 1.0.2 Beta 4 plus the feasibility audit.
DriverBuild: `1.1.0-beta.1-enterprise`; numeric bundle/kmod version: `1.1.0`.

## Scope

- Accept selected RSN AKM 00:0f:ac:1 with CCMP pairwise and group cipher.
- Require a structurally valid, single-AKM/single-pairwise client RSN IE.
- Permit Enterprise association without a pre-existing PSK/PMK. Expose the
  associated link to macOS for EAPOL, keeping the ordinary data port closed.
- Forward non-key EAPOL to the macOS EAP client. Accept the current STA's
  32-byte MSK-derived PMK (Apple cipher 9) or PMK (cipher 6) callback.
- Use the existing internal WPA2 four-way/group handshake, preserving the
  selected Enterprise RSN in association and M2. Ignore EAPOL-Key before PMK;
  the AP must retransmit if the callback races M1. Do not run a second
  external PTK/GTK handler for the Enterprise association.
- Open ordinary TX/RX only after GTK/PTK install and successful M4 submission.
  EAP-Success and a PMK callback alone never authorize data. Submission does
  not prove AP acceptance; that still requires runtime validation.
- Bound initial EAP authentication to 120 seconds and reuse existing key
  erasure on disconnect, Wi-Fi off and system sleep.
- Preserve the WPA2-Personal internal handshake and previous sleep/RX fixes.

## Deliberately unsupported in beta 1

PMF-capable/required client selections, SHA256/192-bit/WPA3 Enterprise, WPA1
Enterprise, TKIP Enterprise and PMKSA/preauthentication/fast roaming caching.
No username, password, certificate, PMK or MSK bytes are logged by this feature.
The older Ventura SDK key structure holds only 32 bytes; it accepts the WPA2
PMK portion, not a full 64-byte MSK structure. Other callback ABI variants are
unsupported and must fail validation.

## Validation and limits

Host tests exercise production RSN/auth parsing, EAPOL bounds, controlled-port
policy, PMK installation/idempotence/BSSID binding, and actual key cleanup.
The existing RX/AWDL/link-wake tests and native macOS build must also pass.
These are not over-the-air PEAP or EAP-TLS tests. No physical Enterprise AP
and RADIUS test is available here; this feature must remain experimental.
RTL8814AE remains experimental. No 2.0.0 beta feature merge or TX batching.

## Tests for the next hardware tester

1. Keep 1.0.2 in a fallback EFI; replace only AirPortRTW and reboot.
2. Confirm DriverBuild, then verify existing WPA2-Personal, open Wi-Fi,
   network switching, normal traffic and sleep/wake still work.
3. On an authorized WPA2-Enterprise CCMP network, configure credentials and
   server-certificate validation in macOS. Start with a fresh profile with
   no PMKSA/fast-roaming cache and no PMF requirement.
4. Check EAP identity/method exchange, PMK callback, M1/M2/M3/M4, DHCP and
   bidirectional traffic; test rejection with invalid credentials.
5. Test disconnect/reconnect, Wi-Fi toggles and sleep during authentication.
   A failed/incomplete login must never pass ordinary data.
6. Record method (PEAP/EAP-TLS), chip, OS and redacted logs. Never disable
   server-certificate verification to make an Enterprise test pass.
